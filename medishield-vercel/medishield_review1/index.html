01 — Problem & motivation

What problem are we solving?

Medical vision models are usually evaluated on accuracy alone. A model can be highly accurate on average and still be wrong, confidently, on the one case in front of you — and today's pipelines have no way to flag that.

Why it matters

  • A high-confidence prediction is not automatically a trustworthy one.
  • A classifier can be wrong with high confidence, unstable under small input changes, or fragile against adversarial and everyday image degradation (noise, blur, compression, brightness shifts).
  • Its explanations (e.g. Grad‑CAM) can shift under perturbation without any visible warning to the user.
  • It can silently encounter inputs outside the distribution it was trained on.

Who is affected

Anyone relying on an automated skin-lesion classifier as a decision-support signal — dermatology triage tools, telehealth screening, and research pipelines — inherits this blind spot whenever the system outputs a number with no indication of how much to trust it.

Research question

Can we detect when a medical vision model's prediction has become unreliable, especially under adversarial or realistic image perturbations?
  1. How much does model performance degrade under FGSM and PGD attacks?
  2. Does model confidence change when the input is perturbed?
  3. Can behavioral features help detect incorrect predictions?
  4. Can an XGBoost reliability model distinguish trustworthy from suspicious predictions?
  5. Can abstention reduce error among predictions the system chooses to accept?
  6. Do explanations change when the input is manipulated?
02 — Proposed solution

What we're building

A reliability and safety layer wrapped around a medical image classifier — the system evaluates not only what it predicts, but whether its own behavior gives evidence the prediction can be trusted.

Classification→ Attack→ Observe behavior→ Detect unreliability→ Abstain→ Explain

How it solves the problem

Instead of trusting the classifier's own confidence score, a second, independently trained model (XGBoost) learns — from ground-truth correctness, not an arbitrary threshold — what a reliable prediction looks like versus a suspicious one. When reliability is low, the system abstains and routes the case to a human reviewer rather than forcing an answer.

Not the pitch: "We trained a skin-cancer classifier."
The pitch: "We built a reliability and safety layer around a medical vision model and tested whether it can recognize when its own prediction becomes unreliable."
03 — System architecture

System & technical architecture

Scope note

MediShield is a single research pipeline, not a multi-tier web application. There is no database and no backend API layer — the "frontend" is a Streamlit page that calls the ML pipeline directly in-process. The only external service is the HAM10000 dataset download and (optionally) Google Colab for GPU training compute.

3.3 Data flow: Input → Processing → AI/ML → Decision → Output

  1. Input: user uploads a dermoscopic image
  2. Processing: resize to 224×224, ImageNet normalization; optionally apply FGSM / PGD / stress perturbation
  3. AI/ML: EfficientNet‑B0 → class probabilities, confidence, deep features → reliability feature engine → XGBoost → reliability score
  4. Decision: reliability score vs. threshold → Accept or Abstain
  5. Output: Accept → predicted class + Grad‑CAM heatmap shown to the user. Abstain → case flagged "human review recommended," no prediction forced

Leakage prevention rule

✕ Bad split

Same lesion's images split across Train and Test — leaks lesion-specific cues.

✓ Correct split

All images of a given lesion go to the same split — split happens at lesion_id level, never image level.

06 — Key features & workflow

Key features & workflow

How a user will interact with the system

  1. Upload a skin-lesion image to the Streamlit interface
  2. System returns predicted class, model confidence, and a reliability score
  3. If reliability is high → prediction is shown with a Grad‑CAM heatmap
  4. If reliability is low → system abstains and flags the case "human review recommended" instead of forcing an answer
  5. Optional: user triggers a stress test (FGSM / PGD / noise / blur / brightness / compression) to see how the prediction, confidence, and reliability shift

07 — Innovation / novelty

What differentiates this from a basic classifier

A second model judges trust, not just confidence

Reliability is learned by a separate XGBoost model trained on behavioral features — not read off the softmax output, which a plain classifier would do.

Labels come from correctness, not a threshold

Reliability = 1 when the classifier was actually right, 0 when wrong — never confidence > 0.5, which would just reproduce an arbitrary cutoff.

Adversarial + everyday robustness, combined

FGSM/PGD attacks are paired with realistic degradations (noise, blur, brightness, compression) in one stress suite, instead of only adversarial or only accuracy metrics.

Coverage vs. selective risk, not plain accuracy

Evaluation reports how error changes as the system becomes more selective — a stronger, decision-relevant result than a single accuracy number.

Explanation stability as a signal

Grad‑CAM is compared clean vs. perturbed to flag when the model's own reasoning shifts — not used merely as a static visualization.

Abstention as a first-class output

The system can decline to answer. That option doesn't exist in a standard classifier pipeline.

09 — Impact, scalability & future scope

Impact, scalability & future scope

Real-world relevance

A reliability layer that flags low-confidence-or-unstable predictions for human review is directly useful anywhere an AI model is used as a decision-support signal rather than a final answer — e.g. triage screening tools that need a defensible "when not to trust the model" behavior.

Scalability

The reliability layer is architecturally model-agnostic: the same "extract behavioral features → train a separate reliability detector → threshold into accept/abstain" pattern could wrap other medical imaging classifiers beyond skin lesions, given retraining on the new task's features.

Limitations (stated on purpose)

  • HAM10000 is a benchmark dataset, not a full clinical population.
  • The three-class scope is narrowed, not comprehensive dermatology coverage.
  • Adversarial attacks are controlled experiments, not a simulation of every real failure mode.
  • Reliability detection based on correctness does not prove clinical safety.
  • Grad‑CAM highlights what the CNN attended to — not guaranteed clinical reasoning.
  • Not a replacement for a dermatologist or a clinical diagnostic workflow.

Future scope

Out-of-distribution detection Advanced uncertainty methods Additional attack types Advanced explanation-shift metrics Broader dataset / more classes Hyperparameter tuning at scale

Preferred language going forward: "research prototype," "model reliability," "human-review escalation." Avoided: "clinically safe," "prevents misdiagnosis," "doctor replacement."
